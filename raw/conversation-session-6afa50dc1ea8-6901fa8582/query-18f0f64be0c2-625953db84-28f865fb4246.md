## Agent

这里的"computer use"通常指让 AI 像人一样看屏幕、点鼠标、敲键盘来操作电脑（Computer-Use Agent / GUI Agent）。按"封装完整、开箱即用"程度分类，目前主流开源项目如下：

## 一、桌面级完整 CUA（直接控制鼠标键盘，最接近"开箱即用"）

| 项目 | 特点 |
|---|---|
| **UI-TARS Desktop**（字节跳动） | 端到端视觉模型，看截图直接输出操作，跨 Windows/macOS，带桌面应用、CLI、Web UI 和 MCP 工具，还支持远程控制电脑。是目前上手门槛最低的桌面 CUA 之一 [^src_e118aad2ca392589] [^src_ed99ed61a3c4b4ce] |
| **Agent S / Agent S3**（Simular） | 层次化规划 + 反思机制，Agent S3 宣称在 OSWorld 基准上首次超过人类水平（约 72.6%）。偏研究/框架型，但能力完整，覆盖 Linux/macOS/Windows [^src_d5fcbcd1e15609fe] |
| **Open Interpreter** | 代码解释器路线：让模型在本地终端执行 Python/Shell 来操作系统，处理文件、表格、脚本类任务最稳定；自带 OS 模式可做 GUI 操作，兼容 Ollama 等本地模型 [^src_e8704c43055d8682] [^src_62d538217fffb46e] |
| **UFO / UFO³**（微软） | Windows 深度控制专精，走 UI Automation / Win32 / COM 原生接口，特别适合 Office、资源管理器等微软系应用自动化 [^src_e118aad2ca392589] |
| **TuriX-CUA** | 基于 VLM + macOS AXUIElement 可访问性树，四角色并行流水线架构，提供 macOS/Windows 桌面应用，还直接以 Skill 形式接入 OpenClaw 这类 Agent 框架 [^src_30ceeed13cb67cd8] |
| **Bytebot** | 自托管容器化 Linux 桌面 Agent，自然语言控制隔离环境，安全性更好 [^src_037e21951f99e6a0] |
| **PC-Agent**（上海交大 GAIR） | 收集人类操作轨迹训练的多智能体系统（规划 + 视觉定位），MIT 协议，适合办公自动化场景 [^src_8047af555733bd30] [^src_0d2e6497903b6ed6] |

## 二、浏览器专精类（封装成熟、生产可用度最高）

- **browser-use**（约 10 万+ Star）：浏览器自动化领域事实上的标杆，模型无关（可接任意 LLM 甚至本地 Ollama），Python SDK 极简 [^src_42b4022fb5a80be7]
- **Stagehand**：Playwright 之上的自然语言 + 代码混合浏览器 SDK，动作自愈、对 UI 变化鲁棒 [^src_cab063c55e929d5e]
- **Skyvern**：视觉 + 多 Agent 浏览器工作流，擅长表单填写、动态页面、验证码场景 [^src_42ec1c2080ee4ff3]
- **Midscene.js**：视觉驱动的跨平台 UI 自动化 [^src_1e86335197ad725b]

## 三、基础设施 / 组件（不算完整产品，但封装了核心能力）

- **Cua**（trycua）：跨平台原生驱动层 + 沙箱 + 评测工具，适合自己构建 CUA 而非直接使用 [^src_da05a98e67453da8]
- **OmniParser V2**（微软）：屏幕解析组件，把截图转成结构化可点击元素（SoM 标注），常被用来给其他 Agent 做"眼睛" [^src_e8704c43055d8682]
- **ComputerRL**（清华、智谱、国科大）：强化学习训练桌面 Agent 的研究框架 [^src_7154a7067960bd88]

## 选型建议

- 想**快速体验** AI 操控自己电脑：UI-TARS Desktop 或 TuriX
- 想**稳定自动化浏览器**：browser-use
- 想**自动化 Office/Windows**：UFO
- 想**本地私有化、处理脚本/文件任务**：Open Interpreter + 本地模型
- 想**做研究或构建自己的 CUA**：Agent S、Cua、OmniParser

两点提醒：这些项目普遍会真实控制鼠标键盘，务必在虚拟机/容器或非生产环境运行，并对生成的操作逐条确认 [^src_e118aad2ca392589]。另外该领域迭代极快，选型前建议核对各仓库的最近提交和 OSWorld/WebVoyager 类基准表现 [^src_037e21951f99e6a0]。

## 内部知识库命中（封装完整类）

内部知识库里收录了两个与 computer use 直接相关的项目，而且恰好都属于"内置封装好的完整能力"这一类型：

### 1. Hermes Agent（Nous Research）— 内置完整浏览器自动化工具集 [^src_23f4aa07ad54dc28] [^src_5cec9de6f1f018a7]

知识库页面明确记载它**内置了一整套 `browser_*` 工具**，开箱即用 [^src_5cec9de6f1f018a7]：

- `browser_navigate` / `browser_snapshot`（可访问性树快照，元素带 `@e1`/`@e2` 引用 ID）
- `browser_click` / `browser_type` / `browser_scroll` / `browser_press` / `browser_back`
- `browser_vision`（截图 + 视觉 AI 分析，用于验证码等）
- `browser_console`（读日志 / 执行 JS）
- `browser_cdp`（原始 CDP 透传）
- `browser_dialog`（显式处理 alert/confirm/prompt）
- `browser_get_images`

后端模式很全：Browserbase 云、Browser Use 云/本地（默认）、Firecrawl 云、Camofox 本地反检测、本地 Chromium CDP、agent-browser CLI [^src_a516d5a1afea7dae]。不过知识库也标注了一个事实边界：**raw 未明确 Hermes Agent 自身是否开源**，仅确认 Browser Use 是开源框架 [^src_478ab553ca46576e]。

### 2. Browser Use — 独立开源浏览器自动化框架 [^src_da1e25f65e46ee86] [^src_63028a421ab20fa8]

- Python 库/CLI（Browser Use CLI 3.0），可单独驱动本地 Chrome 或 Browser Use 云浏览器 [^src_da1e25f65e46ee86]
- 与 Hermes 的关系：Hermes 依赖它作为**默认后端模式**，二者是独立产品，不是同一项目 [^src_6cade05db3ab0983] [^src_8d1eba8c8bcce990]

## 四个站各是什么

### 1. 菜鸟教程 · Pi Agent 教程 — 纯"使用手册" [^src_603213ad785bc06c]

完整教程系列：简介、核心概念、安装、认证与模型配置（含 DeepSeek 接入）、第一次对话、交互/非交互模式、上下文与会话管理、Skills、扩展开发、事件系统、包管理、多平台部署，外加 CLI/配置/Provider 参考手册。**完全不碰源码**，只教"怎么用"：怎么装、怎么配、四种运行模式、内置工具、怎么扩展。零门槛。

### 2. PI from Scratch — 从零手写 600 行教学版 [^src_7b49bff74f236ad7]

基于生产级 pi（上万行）提炼的 **nanopi（600 行）**，用一篇文章跟着数据流把五个 TS 文件（`llm.ts` / `agent.ts` / `tools.ts` / `tui.ts` / `cli.ts`）从头写出来。交互式阅读：右侧编辑器随文章滚动浮现代码，带"语法扫盲块"打消 TS 顾虑。作者明说是给初学者写的。核心价值是把 Agent Loop、工具与事件流、模块单向依赖这些原理用最少的代码讲透。

### 3. π-agent book（books.antinomie.org）— pi-agent-core 逐行源码导读 [^src_601872ed4f99cda2] [^src_c8fb71b1516bcd5b]

主角是 **pi-agent-core 这个库本身**（不是整个 pi）。目前只有 2 章：第 1 章"它是什么"，第 2 章跟着一次 `prompt()` 把控制流从 `prompt()` 走到 `agent_end` 走完全程。交互式设计很讲究：每个论断都链回仓库里它出生的那一行，代码块可"钉"在屏幕角落对照。注意它是**进行中的书**，每周只更一章，目前是预览版。

### 4. 冬瓜 · 源码精读笔记 — 生产级 Pi Agent 全景精读 [^src_efe843bf731893fd]

10 章完整精读，约 5 万字，覆盖整个 pi 的三层架构（pi-ai / agent-core / coding-agent）：Agent Loop、30+ 供应商模型调用抽象、工具系统五步管道、7 种消息系统、事件驱动、上下文工程与压缩、Session Tree 会话管理。**每章都有 TypeScript 和 Python 两个版本**（Python 为转写）。自我定位就是"想搞懂一个生产级 Agent SDK 是怎么造出来的"。

| 站点 | 内容类型 | 门槛 | 适合人群 |
|---|---|---|---|

## 从小白到有基础的路线

1. **纯小白** → 从**菜鸟教程**开始 [^src_603213ad785bc06c]。先装上、跑起来、知道交互/Print/JSON/RPC 四种模式、会用内置工具和 Skills，建立"agent 是什么"的直觉。不要一上来碰源码。
2. **会用之后想懂原理** → **PI from Scratch** [^src_7b49bff74f236ad7]。跟着手写一遍 nanopi，Agent Loop、工具、事件流、层与层之间为什么这样拆，600 行里全讲明白了。这是原理理解的最短路径。
3. **想深入具体库源码** → **π-agent book** [^src_601872ed4f99cda2]。但它只写 pi-agent-core、目前仅 2 章且每周更新，适合作为长期跟读，不适合一次性系统学习。
4. **想掌握生产级全貌** → **冬瓜精读笔记** [^src_efe843bf731893fd]。覆盖面最完整，且有 Python 版，对你教 Python/LangChain 的背景来说阅读成本最低——可以直接用它的 Python 版做教学素材。

两点提醒：π-agent book 和冬瓜笔记都聚焦源码，阅读前最好先把 Pi 跑起来用过一轮；另外这四个站的主题是同一个 pi 项目，但层级不同——菜鸟教使用，PI from Scratch 讲最小实现，π-agent book 精读 pi-agent-core 一个库，冬瓜精读整个三层架构，四者不冲突，可以按上面顺序串起来读。
