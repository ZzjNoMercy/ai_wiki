## ACP 是什么

Agent Client Protocol（ACP）定义了 AI 智能体（coding agent）与客户端应用（如代码编辑器/IDE）之间的标准通信接口。它标准化了代码编辑器与编码智能体之间的通信，既适用于本地场景，也适用于远程场景。

## 为什么需要 ACP

AI 编码智能体和编辑器紧密耦合，但互操作并不是默认存在的：每个编辑器都要为想支持的每个智能体做定制集成，智能体也要实现编辑器专属 API 才能触达用户。这带来三个问题：

1. **集成开销**：每一个新的"智能体×编辑器"组合都需要定制开发工作。
2. **兼容性有限**：智能体只能工作在少数编辑器上。
3. **开发者锁定**：选择一个智能体往往意味着接受它提供的固定接口。

ACP 通过提供标准化的"智能体-编辑器"通信协议解决这些问题，思路与 Language Server Protocol（LSP）标准化语言服务器集成类似：实现 ACP 的智能体可以配合任何兼容编辑器工作；支持 ACP 的编辑器可以接入整个 ACP 兼容智能体生态。这种解耦让双方可以独立创新，开发者可以自由选择最适合自己工作流的工具。

## 适用场景

- **本地智能体**：作为代码编辑器的子进程运行，通过 stdio 上的 JSON-RPC 通信。
- **远程智能体**：托管在云端或独立基础设施上，通过 HTTP 或 WebSocket 通信（远程智能体的完整支持仍在完善中，官方正与相关平台协作推进）。

协议尽可能复用 MCP 中的 JSON 表示，同时为有用的 agentic 编码 UX 元素（如显示 diff）提供自定义类型。用户可读文本的默认格式是 Markdown，可以在不需要编辑器渲染 HTML 的前提下表达富格式。

## 架构设计哲学

1. **MCP 友好**：协议基于 JSON-RPC 构建，并尽量复用 MCP（Model Context Protocol）的已有类型，集成方不需要为常见数据类型再发明一套表示。
2. **UX 优先**：专为"与 AI 智能体交互的用户体验问题"设计——足够灵活地清晰呈现智能体的意图，但不过度抽象。
3. **可信模型**：ACP 适用于"在代码编辑器里和一个你信任的模型对话"的场景。编辑器仍可控制智能体的工具调用，同时把本地文件和 MCP 服务器的访问权限交给智能体。

## 连接方式（Setup）

- 用户尝试连接智能体时，编辑器**按需启动智能体子进程**，所有通信通过 **stdin/stdout** 进行。
- 每个连接可支持**多个并发会话**，可同时进行多条"思路线"。
- 大量使用 **JSON-RPC 通知（notifications）**，让智能体实时向 UI 流式推送更新。
- 利用 JSON-RPC 的**双向请求**，智能体也可以反过来向编辑器发请求——例如请求某个工具调用的权限。

## MCP 集成方式

- 编辑器通常带有用户配置好的 MCP 服务器。转发用户 prompt 时，编辑器把这些 **MCP 配置一并传给智能体**，让智能体直接连接对应的 MCP 服务器。
- 编辑器自己也可能想把某些功能导出为 MCP 工具。做法不是在同一 socket 上同时跑 MCP 和 ACP，而是**编辑器提供自己的 MCP server 作为配置**；由于有些智能体只支持 stdio 方式的 MCP，编辑器还可以提供**小代理（proxy）**把请求隧道转发回自己。

## ACP Registry

ACP Registry 是查找和安装 ACP 兼容智能体的最简单方式，是经官方策展的智能体集合（仅收录支持 authentication 的智能体），开发者可借此把 ACP 兼容智能体分发给任何支持该协议的客户端。

客户端可以编程方式获取 registry：`curl https://cdn.agentclientprotocol.com/registry/v1/latest/registry.json`。registry JSON 包含所有智能体元数据（含用于自动安装的分发信息）。

**提交你的智能体**：
1. Fork registry 仓库（github.com/agentclientprotocol/registry）。
2. 用你的智能体 ID 创建文件夹（小写、允许连字符）。
3. 按 schema 添加 agent.json（agent.schema.json）。
4. 可选添加 icon.svg（推荐 16x16）。
5. 提交 Pull Request。
