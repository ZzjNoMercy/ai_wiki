# AIHOT

AIHOT 是微信公众号《分享2个Vibe Coding必备的超实用Prompt。》一文作者（署名卡兹克）以纯 Vibe Coding 方式构建的自研 Agent 产品。作者自称"纯粹的不懂代码的小白"，完全依靠 AI 进行开发（[[concepts/vibe-coding|Vibe Coding]]，uses）。

## 功能与形态（文中直接支持）

- 提供"精选消息"并通过飞书推送（精选消息飞书推送）。
- 抓取海外信源（例如 OpenAI 官网），存在抓取规则与流量路由机制；信源增多后曾出现过 100M 的 HTML。
- 精选信息流存在时间戳排序，文章可能进入飞书群 PUSH、RSS 订阅和日报。
- 提供 Skill 能力，Skill 调用量是网页端的 10 倍以上。

## 文中记录的事故与修复

- **飞书推送事故（第一性原理例证）**：某个周五精选消息飞书推送出 BUG，OpenAI 发布 GPT-5.6 这类大新闻在周六凌晨未被推送，周六上午作者收到二十多条用户反馈。Agent 初步排查发现：之前测试国产模型时 OpenAI 的抓取被该国产模型改坏，导致 OpenAI 官网信源断抓约三天。追加"根据第一性原理来找一下原因"后，发现海外信源抓取规则中流量路由层面的深层隐患（该代码原文称写于当年 4 月中旬），表层小错把底层流量路由问题暴露出来；作者花半天时间重构底层路由。
- **对抗式审查例证**：6 月初（Claude Opus 4.8 和动态工作流上线之后）作者开启近 40 个 Agent 对 AIHOT 做对抗式审查（纯找 BUG），找出多个潜在风险：OOM 死循环（后台 worker 处理特别大的任务时内存爆掉被杀后自动重试、再次爆掉被杀的无限循环）、未来时间污染（信源文章因时区错误显示未来时间戳，会排到精选信息流最前面，并进入飞书群 PUSH、RSS 订阅、日报，一篇"来自未来的文章"污染整个信息流）、HTML 清洗模块性能炸弹、翻译模块同类隐患、部署探活缓存穿透假阳性等。

## 数据（文中直接支持）

- 最近一周请求量超过千万。
- Skill 调用量远超作者预期，是网页端的 10 倍以上。
- 作者自述"偶尔出一些小BUG，但是能稳定的为这么多用户提供服务"。
