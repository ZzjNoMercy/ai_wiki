# 跨 Harness 行为蒸馏实践

本实践从 [[papers/harness-zero|Harness-Zero]] 的实验流程提炼，目标是把领域专用 [[concepts/harness|Harness]] 引导出的**可重现行为**，转成固定部署 Harness 下可执行、可观察的训练示范。它描述的是论文在三个任务域验证过的一种做法，不是任意专用 Harness 都能被完整压缩进模型的保证。

## 问题

优化后的专用 Harness 往往附带额外工具、中间件、技能和记忆。若部署需要一个固定、较小的目标 Harness，直接拿专用 Harness 下的成功轨迹做监督，会出现训练与部署接口不一致：学生无法调用轨迹中的专用工具，也可能看不到中间件私下使用的状态或判断依据。

## 根因

模型在每一步只能根据当前可见上下文选择目标 Harness 支持的响应。源 Harness 提供的动作与信息不属于这个条件分布。仅保留任务最终答案或源 Harness 的高分轨迹，不能保证学生学会在目标接口里获取证据、执行检查并处理结果（论文第 1、3 节及表 3）。

## 方案

1. **固定目标接口。** 在数据采集、训练和部署时使用同一个目标 Harness `h`，明确它允许的动作和学生可见的观察。
2. **形成有证据的专用指导。** 从训练任务的反复失败中优化专用 Harness `h*`；只纳入一类任务可复用的工具、控制规则、技能或记忆，避免写入具体训练题答案（附录 A）。
3. **相对于 `h` 改写指导。** 把 `h*` 的工具转为 `h` 中可执行的动作配方，把中间件转为审查条件，把技能和记忆转为识别失败与修正动作的参考规则 `K`（附录 B）。
4. **在执行前审查学生响应。** 学生在 `h` 下提出动作；审查 Agent 读取当前学生可见轨迹和私有 `K`，对合理动作放行，只在必要时替换为最小、完整且可由 `h` 执行的响应。审查 Agent 不私下访问学生环境、隐藏答案或验证器反馈；新增任务证据要经 `h` 执行后进入学生可见轨迹（第 3.2 节）。
5. **只训练可部署行为。** 用被接受的目标 Harness 轨迹做 SFT，屏蔽可能泄入样本的审查者视角推理。部署时撤掉 `h*`、`K` 和审查 Agent，单独测试更新后的模型加 `h`（第 3.3 节）。

## 验证

- 同一基座模型下比较固定 `h`、基座模型挂载 `h*`、以及蒸馏模型仅使用 `h`；不能把专用 Harness 仍在运行时的收益算成权重内化。Harness-Zero 的三域宏平均结果分别为 23.3%、41.7%、44.3%（表 2）。
- 在未参与训练的任务上检查任务成功率，并逐项核对预先列出的专用行为是否由蒸馏模型在 `h` 中自行重现。论文对 28 个行为模式报告平均 82.3% 恢复率（表 4）。
- 对照直接强模型轨迹、专用 Harness 轨迹和没有专用规则的审查轨迹，检验收益来自可学习的过程指导，而不只是采集时有更强模型或更高任务成功率（表 3）。
- 单独记录数据采集时的额外调用与延迟、部署时的运行成本，避免把一次性训练成本混作部署收益。

## 适用范围

- 专用 Harness 已找到反复有效的检查、检索、操作和纠错流程，且这些流程能改写成目标 Harness 的动作；
- 有可评价的训练任务、独立测试任务，并能保留学生实际可见的动作和观察；
- 希望将多个领域指导汇入同一模型，同时继续使用固定目标 Harness 的工具与执行边界。

## 失效条件与边界

- 目标 Harness 无法取得某项外部信息或执行等价动作时，模型不能仅凭蒸馏补出缺失的权限或工具；需要保留外部能力或扩展目标接口。
- 审查 Agent 不够可靠时，错误替换会污染示范；论文指出弱审查模型可能使审查有害。
- 专用 Harness 的收益主要来自深层领域知识、复杂工具功能或无法写成响应的上下文管理时，响应级 SFT 可能只能部分迁移；论文在 USPTO 上报告蒸馏模型仍低于挂载 `h*` 的基座模型。
- 逐步审查增加采集成本；论文的 USPTO 试验平均延迟为 2.4 倍。该数字只覆盖其报告的配置，不代表其他任务的固定开销。
- 论文比较了多种 SFT 监督来源，但没有直接 RL 后训练对照；不能据此断定本流程优于直接强化学习。
